# 后端架构与技术说明

## 1. 后端定位

后端负责为数字逻辑电路仿真教学系统提供 HTTP API，主要能力包括：

1. 提供器件库元数据，供前端渲染器件面板、引脚和属性。
2. 保存、读取、更新和删除电路工程。
3. 校验电路 JSON，包括器件、引脚、连线、悬空输入和输出冲突。
4. 调用 C++ 仿真核心的 Python 绑定运行电路仿真。
5. 返回仿真结果、最终节点状态和波形变化点。

后端不负责在 Python 中重新实现数字逻辑仿真规则。完整仿真计算由 C++ `logic_sim` pybind11 模块承担，Python 后端只做 API 编排、数据校验和结果格式转换。

## 2. 技术栈

| 技术 | 用途 |
| --- | --- |
| Python 3 | 后端服务实现语言。 |
| FastAPI | HTTP API、路由、请求/响应模型绑定。 |
| Pydantic v2 | 电路 JSON、器件元数据、仿真结果和工程数据建模。 |
| SQLite | 本地工程持久化存储。 |
| sqlite3 | 标准库 SQLite 访问，避免额外异步数据库依赖。 |
| pybind11 模块 `logic_sim` | C++ 仿真核心的 Python 调用入口。 |
| httpx | 后端 API 测试客户端。 |
| pytest | 后端单元测试和 API 测试。 |

## 4. 应用入口

入口文件：

```text
backend/app/main.py
```

职责：

1. 创建 FastAPI 应用实例。
2. 配置 CORS，允许前端开发服务器访问。
3. 将 C++ 构建目录加入 `sys.path`，用于导入 `logic_sim`。
4. 注册 API 路由。
5. 提供健康检查接口。

当前注册的路由模块：

| 模块 | 前缀 | 职责 |
| --- | --- | --- |

```text

```

主要模型：

| 模型 | 说明 |
| --- | --- |
| `PinDef` | 器件引脚定义。 |
| `DeviceDef` | 单个器件元数据。 |
| `DeviceLibraryIndex` | 器件库索引信息。 |
| `DeviceInstance` | 电路中的器件实例。 |
| `WireEndpoint` | 连线端点，包含 `device` 和 `pin`。 |
| `WireDef` | 电路连线，JSON 字段 `from` 映射到 Python 字段 `from_`。 |
| `ProbeDef` | 示波器/逻辑分析仪探针定义。 |
| `CircuitDef` | 完整电路 JSON。 |
| `SimOptions` | 仿真运行参数。 |
| `SimResult` | 仿真结果。 |
| `ValidationResult` | 电路校验结果。 |
| `ProjectMeta` / `ProjectData` | 工程元数据和完整工程数据。 |

电路 JSON 基本结构：

```json
{
  "version": "1.0",
  "devices": [
    {
      "id": "u1",
      "type": "AND",
      "x": 100,
      "y": 100,
      "params": {
        "delay": 1,
        "inputs": 2
      }
    }
  ],
  "wires": [
    {
      "id": "w1",
      "from": { "device": "u1", "pin": "Y" },
      "to": { "device": "u2", "pin": "I" }
    }
  ],
  "probes": []
}
```

## 6. 器件库服务

实现文件：

```text
backend/app/services/device_library.py
```

数据来源：

```text
device-library/devices.json
device-library/gates.json
device-library/flip_flops.json
device-library/chips.json
```

服务职责：

1. 启动时按需加载器件库 JSON。
2. 将 `pins` 和 `output_pins` 合并为统一的 `DeviceDef.pins`，便于校验。
3. 注册器件别名，例如 `74138` 指向 `74LS138` 的同一类能力。
4. 提供按类型、类别和全部列表查询。

API：

```http
GET /api/devices
GET /api/devices?category=gate
GET /api/devices/{device_type}
GET /api/devices/index
GET /api/devices/types
```

## 8. 电路校验

实现文件：

```text
backend/app/services/validation_service.py
```

校验入口：

```http
POST /api/circuits/validate
POST /api/simulations/validate
```

其中 `/api/circuits/validate` 是设计文档约定路径，`/api/simulations/validate` 是当前兼容路径。

已实现校验规则：

| 规则 | 结果 |
| --- | --- |
| `device.id` 重复 | error |
| 未知 `device.type` | error |
| 连线引用不存在的器件 | error |
| 连线引用不存在的引脚 | error |
| 输入引脚悬空 | warning |
| 多个输出引脚驱动同一连通网络 | error |

输出冲突检测方式：

1. 先过滤端点合法的连线。
2. 使用并查集将所有连线端点合并成连通网络。
3. 遍历每个网络中的引脚。
4. 如果同一网络内存在两个或更多 `direction == output` 的引脚，则生成 `Output conflict` 错误。

这可以覆盖直接输出相连，也可以覆盖两个输出同时接到同一个输入节点的情况。

## 9. 仿真服务

实现文件：

```text
backend/app/services/simulator_service.py
```

API：

```http
POST /api/simulations/run
POST /api/simulations/step
POST /api/simulations/reset
```

`POST /api/simulations/run` 流程：

1. FastAPI 将请求体解析为 `CircuitDef` 和 `SimOptions`。
2. 后端先调用 `ValidationService.validate()`。
3. 如果校验有 error，返回 `422`。
4. 检查 `logic_sim` Python 模块是否可导入。
5. 将 Pydantic 电路模型转换为 C++ 绑定需要的 dict。
6. 调用 `logic_sim.run(circuit_dict, options_dict)`。
7. 将 C++ 返回的 dict 转换为 `SimResult`。
8. 将校验 warning 合并到仿真结果。

仿真请求示例：

```json
{
  "circuit": {
    "devices": [
      { "id": "u1", "type": "NOT", "params": { "delay": 1 } }
    ],
    "wires": []
  },
  "options": {
    "max_ticks": 10,
    "record": ["u1.Y"],
    "default_delay": 1
  }
}
```

仿真结果核心字段：

| 字段 | 说明 |
| --- | --- |
| `status` | `ok`、`error` 或 `timeout`。 |
| `errors` | 仿真错误列表。 |
| `warnings` | 校验和仿真 warning。 |
| `final_nodes` | 最终节点值。 |
| `waveform` | 波形变化点。 |
| `ticks_elapsed` | 已执行 tick 数。 |
| `events_processed` | 已处理事件数。 |

当前限制：

1. `step` 和 `reset` 只是接口占位；C++ pybind11 当前未暴露可持久化的 `Simulator` 实例，因此不能真正维护逐步仿真会话。
2. 设计文档中的 WebSocket `/ws/simulations/{id}` 当前尚未实现。

## 10. 错误处理

主要错误路径：

| 场景 | HTTP 状态 |
| --- | --- |
| 获取不存在的器件 | `404` |
| 获取、更新、删除不存在的工程 | `404` |
| 运行仿真前电路校验失败 | `422` |
| C++ 仿真核心不可用 | `503` |
| C++ 仿真运行时异常 | 返回 `SimResult(status="error")` |

校验接口本身不返回 `422`，而是始终返回结构化 `ValidationResult`，由调用方根据 `valid` 判断是否可运行仿真。

## 12. 与 C++ 仿真核心的关系

后端通过 Python 模块名 `logic_sim` 调用 C++ 仿真核心。入口文件会尝试把以下构建目录加入 `sys.path`：

```text
build/sim-core
```

如果 `logic_sim` 不可导入：

1. `/api/health` 的 `sim_core_available` 返回 `false`。
2. `/api/simulations/run` 返回 `503`。

后端传给 C++ 的电路 dict 当前只包含：

1. 器件 `id`。
2. 器件 `type`。
3. 器件 `params`。
4. 连线 `from` / `to`。

坐标、探针等前端展示字段不会传给 C++ 仿真核心。

## 13. 当前状态与后续建议

当前已满足后端核心 API、工程保存、器件库查询、电路校验和批量仿真调用能力。后端测试已通过。

后续建议：

1. 将 FastAPI startup 从 `@app.on_event` 迁移到 lifespan。
2. 在 C++ pybind11 暴露会话式 `Simulator` 后，完善 `/api/simulations/step` 和 `/api/simulations/reset`。
3. 按设计文档实现 WebSocket `/ws/simulations/{id}`。
4. 为 `SimOptions.floating_input` 接入 C++ 参数或移除此暂未使用字段。
5. 如果工程数量增多，可为 SQLite 增加索引、分页和工程名称搜索。

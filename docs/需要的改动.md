# 数字逻辑电路仿真系统需要的改动

## 1. 本次检查结论

本次按普通使用者视角检查了已启动的前后端。后端接口链路基本可用，前端可以加载页面、保存工程、加载工程、调用校验和仿真接口。

真正阻碍使用的是前端编辑器能力不完整：

1. 器件拖到画布后不能移动。
2. 器件不能从界面删除。
3. 用户不知道怎样接入 `0/1` 输入信号，实际也缺少可拖拽的信号源器件。
4. 运行仿真后多数门电路因为输入悬空只得到 `X/Z`，界面没有把“输入悬空”作为明显问题提示给用户。
5. 连线、保存、加载、示波器都有基础能力，但缺少清晰、可持续使用的工作流。

## 2. 已验证可用的能力

后端直连检查结果：

| 场景 | 结果 |
| --- | --- |
| 健康检查 | 可用，`sim_core_available=true`。 |
| 获取器件库 | 可用，能返回门电路等器件元数据。 |
| 电路校验 | 可用，能返回 warning/error。 |
| 输出冲突校验 | 可用，能识别多个输出驱动同一网络。 |
| 非法引脚校验 | 可用。 |
| 未知器件校验 | 可用，例如 `SWITCH` 当前会被判定为未知器件。 |
| 运行仿真 | 可用，能返回 `final_nodes` 和 `waveform`。 |
| 保存工程 | 可用。 |
| 加载工程 | 可用。 |

示例问题：一个 `AND -> NOT` 电路在没有输入信号源时可以仿真，但结果是 `X`，并返回悬空输入 warning。

## 3. 高优先级改动

### 3.1 画布器件移动

当前问题：

器件拖到画布后位置固定。用户尝试拖动器件本体不会改变坐标。

需要改动：

1. 给画布中的器件本体添加拖拽或 pointer 移动交互。
2. 拖动时调用状态层的 `moveDevice(id, x, y)`。
3. 拖动过程中连线端点要实时跟随器件位置。
4. 移动时要避免触发选中、连线等其它点击行为。
5. 支持吸附网格，建议默认 20px 或 40px。

验收标准：

1. 拖动已放置器件后，器件位置改变。
2. 保存工程后重新加载，器件保持移动后的位置。
3. 器件移动后已有连线仍连接到正确引脚位置。

### 3.2 删除器件

当前问题：

界面没有删除入口。状态层有 `removeDevice`，但 UI 没有暴露。

需要改动：

1. 选中器件后，在属性面板或工具栏显示删除按钮。
2. 支持键盘 `Delete` / `Backspace` 删除选中器件。
3. 删除器件时同时删除关联连线。
4. 删除前可不弹确认；如果器件有关联连线，可以在删除按钮旁提示会同时删除连线。

验收标准：

1. 选中器件后点击删除，器件消失。
2. 按 `Delete` 可以删除选中器件。
3. 被删除器件相关连线同步消失。

### 3.3 信号源与输出显示器件

当前问题：

器件库只有门电路、触发器、芯片等逻辑器件。用户没有办法拖入可设置的 `0/1` 输入，也没有清晰的 LED/探针/数码管输出器件。

需要改动：

新增 IO 类器件，至少包括：

| 器件 | 作用 |
| --- | --- |
| `INPUT_HIGH` 或 `VCC` | 恒定输出 `1`。 |
| `INPUT_LOW` 或 `GND` | 恒定输出 `0`。 |
| `SWITCH` | 用户可在属性面板切换 `0/1`。 |
| `CLOCK` | 可设置周期，占空比，输出周期信号。 |
| `LED` | 单输入显示 `0/1/X/Z`。 |
| `PROBE` | 单输入，加入示波器记录。 |
| `SEVEN_SEGMENT` | 七段数码管显示。 |

需要同步改动：

1. `device-library` 增加 IO 器件元数据。
2. 后端校验服务接受这些器件类型。
3. C++ 仿真核心或 Python 绑定支持这些器件的仿真语义。
4. 前端属性面板支持修改 `SWITCH`、`CLOCK` 等参数。

验收标准：

1. 用户可以搭建 `SWITCH -> NOT -> LED`。
2. 切换 `SWITCH` 后重新运行，LED 和波形结果变化。
3. 用户可以搭建 `CLOCK -> D 触发器` 基础时序实验。

### 3.4 悬空输入提示

当前问题：

后端会返回悬空输入 warning，但前端运行成功后清空了校验消息，用户不容易看到为什么输出是 `X`。

需要改动：

1. 运行成功也要展示 `result.warnings`。
2. 悬空输入 warning 要定位到具体器件和引脚。
3. 在画布上把悬空输入引脚高亮，例如黄色描边。
4. 属性面板中显示该引脚状态：未连接。

验收标准：

1. 运行只有一个 `AND` 的电路时，界面明确提示 `I0/I1` 悬空。
2. 用户能从提示定位到对应器件和引脚。

## 4. 中优先级改动

### 4.1 连线交互改进

当前问题：

连线依靠点击两个引脚完成，但没有足够提示，也没有在前端限制明显非法连接。

需要改动：

1. 点击第一个引脚后，显示正在连线状态。
2. 鼠标移动时显示临时连线跟随鼠标，而不是固定向右 100px。
3. 高亮可连接引脚，弱化不可连接引脚。
4. 前端即时阻止输入到输入、输出到输出等明显非法连接。
5. 保留后端校验作为最终兜底。
6. 提供取消连线入口：再次点击空白、按 `Esc`。

验收标准：

1. 用户能看懂当前正在从哪个引脚拉线。
2. 输出引脚连到输入引脚可以成功。
3. 输出连输出会在前端直接提示非法。

### 4.2 连线删除方式

当前问题：

点击连线会直接删除，容易误删，也不明显。

需要改动：

1. 点击连线时选中连线，而不是直接删除。
2. 选中连线后支持删除按钮或 `Delete`。
3. 鼠标悬停连线时加粗或高亮。

验收标准：

1. 单击连线不会立即误删。
2. 选中连线后可以明确删除。

### 4.3 属性面板可编辑

当前问题：

属性面板只读，不能改器件参数。

需要改动：

1. 支持编辑器件 ID 或显示名。
2. 支持编辑通用参数：`delay`。
3. 支持编辑门电路输入数量，并同步引脚数量和后端仿真参数。
4. 支持编辑触发器/计数器初始值。
5. 支持编辑 IO 器件参数，例如开关值、时钟周期。

验收标准：

1. 修改参数后保存/加载不丢失。
2. 修改参数后运行仿真使用新参数。

### 4.4 工程管理

当前问题：

保存每次都会创建新工程。加载必须手动输入工程 ID。没有工程列表、覆盖保存、重命名、删除工程入口。

需要改动：

1. 增加工程列表面板或下拉菜单。
2. 支持打开已有工程。
3. 打开工程后“保存”应更新当前工程，而不是总是新建。
4. 支持“另存为”。
5. 支持删除工程。
6. 保存成功后 ID 不应只短暂显示，应在工程状态区持续可见。

验收标准：

1. 用户无需手动记住工程 ID 就能加载工程。
2. 修改已有工程后保存，再加载能看到修改。

### 4.5 示波器和探针

当前问题：

当前运行时默认 `record_all=true`，示波器会记录很多信号；不同器件的 `I/Y` 名称重复，用户难以分辨。

需要改动：

1. 支持用户添加探针。
2. 示波器默认只显示探针或关键输出。
3. 信号名使用 `deviceId.pin` 或用户自定义别名。
4. 支持隐藏、排序、重命名通道。
5. 对 `X/Z` 使用明确视觉样式，不只按低电平画。

验收标准：

1. 两个器件都有 `Y` 时，示波器能区分来源。
2. 用户可以只看自己关心的信号。

## 5. 低优先级改动

### 5.1 画布导航

需要支持：

1. 缩放。
2. 平移。
3. 缩放后拖拽坐标正确换算。
4. 回到全局视图。

### 5.2 器件库使用体验

需要支持：

1. 加载中状态。
2. 加载失败提示。
3. 按型号、中文名、英文名搜索。
4. 常用器件置顶。
5. 分类折叠状态更清晰。

### 5.3 帮助提示

需要补充轻量帮助，但不要做大段说明页：

1. 空画布提示可以包含“拖入信号源和器件”。
2. 第一次点击引脚时提示“再点击另一个引脚完成连线”。
3. 运行后如果没有任何有效输入，提示先添加开关或常量源。

## 6. 后端与核心需要配合的改动

### 6.1 IO 器件支持

需要在后端和仿真核心里支持新增 IO 类型：

1. 常量高/低。
2. 开关。
3. 时钟。
4. LED/探针。
5. 七段数码管。

如果 LED/探针只作为前端显示器件，也至少要明确它们在电路 JSON 中如何被校验和如何被仿真结果映射。

### 6.2 仿真输入机制

需要明确 `params` 中如何表达输入信号：

```json
{
  "id": "sw1",
  "type": "SWITCH",
  "params": {
    "value": "1"
  }
}
```

时钟示例：

```json
{
  "id": "clk1",
  "type": "CLOCK",
  "params": {
    "period": 2,
    "duty": 0.5,
    "initial": "0"
  }
}
```

### 6.3 API 返回信息

仿真结果建议保留 warning，并提供更结构化的 warning：

```json
{
  "severity": "warning",
  "code": "floating_input",
  "device": "u1",
  "pin": "I0",
  "message": "Input pin is unconnected"
}
```

这样前端可以直接高亮对应器件和引脚。

## 7. 建议实施顺序

第一批先解决基础编辑器可用性：

1. 器件移动。
2. 器件删除。
3. 连线选中和删除。
4. 运行后显示 warning。

第二批解决电路可运行性：

1. 增加 `VCC/GND/SWITCH/LED/PROBE`。
2. 后端和仿真核心支持 IO 器件。
3. 属性面板支持开关值和基础参数编辑。

第三批完善工程和示波器：

1. 工程列表和覆盖保存。
2. 探针管理。
3. 示波器通道命名和筛选。

## 8. 本次检查后的服务状态

检查结束后，已停止前端 Vite 服务和后端 Uvicorn 服务。

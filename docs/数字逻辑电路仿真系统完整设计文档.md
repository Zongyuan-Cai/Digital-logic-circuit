# 数字逻辑电路仿真系统完整设计文档

## 1. 文档目标

本文档用于指导 coding agent 分阶段实现一个数字逻辑电路仿真教学系统，并为每个阶段提供明确的实现边界、接口契约、目录结构和测试要求。

项目分为两步：

1. 实现所有元器件：完成 C++ 仿真核心、基础门电路、触发器、PDF 中出现的所有芯片，并为每个器件编写完善测试。
2. 实现完整前后端：完成 Python 后端 API、前端电路编辑器、示波器、工程保存和端到端联调。

本文档合并了器件梳理、仿真核心设计、前后端架构和测试设计。后续只维护这一份文档。

参考 PDF：

- `数字逻辑电路(5组合逻辑电路).pdf`

## 2. 器件库边界

器件库只提供三类器件：

| 类别 | 范围 |
| --- | --- |
| 基本门电路 | AND、OR、NOT、NAND、NOR、XOR、XNOR。 |
| 基本触发器/锁存器 | RS、D、JK、T、门控、主从、边沿、维持-阻塞等。 |
| PDF 中出现的芯片 | 课件中明确出现的 74 系列芯片。 |

以下内容不作为独立可拖拽器件提供，只作为示例工程或教学实验：

| 教学电路 | 搭建方式 |
| --- | --- |
| 任意进制计数器 | 使用计数器芯片和门电路反馈搭建。 |
| 分频器 | 使用触发器或计数器芯片搭建。 |
| 环形计数器 | 使用 `74LS194` 或触发器反馈搭建。 |
| 扭环形计数器 | 使用 `74LS194` 加反相反馈搭建。 |
| 序列发生器 | 使用 `74161`、`74138`、`74151` 等搭建。 |
| 序列检测器 | 使用触发器和门电路搭建。 |
| 显示计数模块 | 使用计数器、`7448` 和七段数码管搭建。 |

## 5. 信号模型

### 5.1 信号值

C++ 核心必须定义统一信号枚举：

| 值 | 含义 |
| --- | --- |
| `ZERO` | 逻辑 0。 |
| `ONE` | 逻辑 1。 |
| `X` | 未知、冲突、非法或不确定。 |
| `Z` | 高阻态，第一阶段可实现基础支持。 |

外部 JSON 使用字符串：

```json
"0"
"1"
"X"
"Z"
```

### 5.2 基本运算规则

| 运算 | 规则 |
| --- | --- |
| NOT | `0 -> 1`，`1 -> 0`，`X -> X`，`Z -> X`。 |
| AND | 任一输入为 `0` 输出 `0`；若无 `0` 且有 `X/Z` 输出 `X`；全 `1` 输出 `1`。 |
| OR | 任一输入为 `1` 输出 `1`；若无 `1` 且有 `X/Z` 输出 `X`；全 `0` 输出 `0`。 |
| XOR | 任一输入为 `X/Z` 输出 `X`；否则按奇偶性输出。 |
| XNOR | XOR 后取反。 |

### 5.3 节点驱动规则

多个引脚连接后形成一个节点。

| 驱动情况 | 节点值 |
| --- | --- |
| 无驱动 | `Z`，若被普通输入读取可视为 `X`。 |
| 单个驱动 `0` | `0`。 |
| 单个驱动 `1` | `1`。 |
| 多个驱动一致 | 对应值。 |
| 多个驱动冲突 | `X`，并生成 `DRIVER_CONFLICT` 告警。 |
| 驱动包含 `X` | 若无法由其他强驱动确定，则为 `X`。 |

## 6. C++ 仿真核心设计

### 6.1 核心类

```text
SignalValue
  ZERO / ONE / X / Z

Pin
  id
  name
  direction
  active_level
  role

Node
  id
  connected_pins
  drivers
  current_value

Device
  id
  type
  pins
  state
  eval()
  on_input_changed()
  reset()

Circuit
  devices
  nodes
  wires
  probes

Event
  time
  node_id
  value
  source_device_id

EventQueue
  push()
  pop_next()
  empty()

WaveRecorder
  watch(node_id, name)
  record(time, node_id, value)
  to_json()

Simulator
  load_circuit(json)
  reset()
  run(options)
  step()
  get_waveform()
```

### 6.2 事件驱动仿真流程

```text
load_circuit
  -> 创建器件、引脚、节点
  -> 校验连线
  -> 计算初始输出
  -> 记录初始波形

run
  -> 取出最早事件
  -> 更新节点值
  -> 记录波形变化
  -> 找到受影响器件
  -> 重新求值
  -> 若输出变化，按 delay 生成新事件
  -> 直到事件队列为空或达到 max_ticks/max_events
```

### 6.3 组合器件求值

组合器件没有内部状态：

```text
outputs = eval(inputs, params)
```

基础门、编码器、译码器、数据选择器、比较器、奇偶校验器、加法器均属于组合器件。

### 6.4 时序器件求值

时序器件有内部状态：

```text
next_state = transition(current_state, inputs, clock_event, async_controls)
outputs = render(next_state)
```

必须支持：

1. 上升沿检测：`0 -> 1`。
2. 下降沿检测：`1 -> 0`。
3. 异步清零/置位立即生效。
4. 同步清零/置数只在有效时钟沿生效。
5. 初始状态配置。
6. 复位。

### 6.5 仿真选项

```json
{
  "max_ticks": 1000,
  "max_events": 100000,
  "record_all": false,
  "record": ["u1.Q0", "u1.Q1", "clock.OUT"],
  "default_delay": 1,
  "floating_input": "X"
}
```

## 7. 器件元数据设计

器件元数据用于前端渲染、后端校验和文档生成。所有器件必须在 `device-library` 中定义。

示例：

```json
{
  "type": "74LS138",
  "name": "74LS138 3-8线译码器",
  "category": "chip",
  "family": "74LS",
  "description": "3线-8线译码器，输出低有效",
  "pins": [
    { "id": "A", "name": "A", "direction": "input", "role": "address", "active": "high" },
    { "id": "B", "name": "B", "direction": "input", "role": "address", "active": "high" },
    { "id": "C", "name": "C", "direction": "input", "role": "address", "active": "high" },
    { "id": "G1", "name": "G1", "direction": "input", "role": "enable", "active": "high" },
    { "id": "G2A", "name": "G2A", "direction": "input", "role": "enable", "active": "low" },
    { "id": "G2B", "name": "G2B", "direction": "input", "role": "enable", "active": "low" },
    { "id": "Y0", "name": "Y0", "direction": "output", "role": "data", "active": "low" }
  ],
  "params": {
    "delay": 1
  }
}
```

元数据测试要求：

1. 每个器件 `type` 唯一。
2. 每个器件至少有一个引脚。
3. 同一器件内 `pin.id` 唯一。
4. `direction` 只能是 `input`、`output`、`bidirectional`。
5. `active` 只能是 `high`、`low` 或省略。
6. PDF 芯片清单中的每个型号必须存在元数据。

### 7.1 PDF 接法一致性要求

本项目的芯片器件必须按 PDF 中的教学符号、引脚命名、有效电平和功能表实现。不得为了代码方便把芯片替换成“功能类似但接法不同”的抽象模块。

一致性要求：

| 项目 | 要求 |
| --- | --- |
| 型号 | PDF 中出现的型号必须能在器件面板中找到。若存在 `74LSxxx` 和 `74xxx` 两种写法，应作为别名映射到同一实现，但前端可显示两个别名。 |
| 引脚名 | 元数据中的 `pin.id` 和 `pin.name` 必须使用 PDF 中出现的引脚名或等价标准名，例如 `CP`、`CR`、`LD`、`EP`、`ET`、`D0-D3`、`Q0-Q3`。 |
| 有效电平 | PDF 中低有效的输入/输出必须在元数据中标注 `active: "low"`，前端符号应显示反相标记。 |
| 连接方式 | PDF 示例电路中使用的连接方式必须能原样搭建，例如 `74161` 的 `CO -> EP/ET` 同步级联、`74138` 的使能端接法、`74LS194` 的 `DSR/DSL` 反馈接法。 |
| 功能表 | C++ 仿真实现必须以 PDF 功能表为准；若 PDF 未覆盖全部非法状态，非法状态处理要在元数据和测试中明确约定。 |
| 前端符号 | 芯片在前端画布中的引脚排列应尽量贴近 PDF 逻辑符号，至少保证引脚名、方向、有效电平和分组一致。 |

不允许的实现方式：

| 不允许 | 原因 |
| --- | --- |
| 用“任意计数器”替代 `74160/74161/74163/74191` | 课件强调不同芯片清零、置数、使能和级联方式不同。 |
| 用通用 MUX 替代 `74153/74LS151` 且隐藏使能端 | PDF 中的使能端和输出形式是教学重点。 |
| 用通用译码器替代 `74LS138/74139/74LS42` 且改变输出有效电平 | 译码器低有效输出会影响接法。 |
| 用理想寄存器替代 `74LS194/74LS195/74195` | 移位方向、串行输入和模式控制端必须可见。 |
| 前端只显示黑盒输入输出，不显示芯片关键控制端 | 教学需要学生按 PDF 原接法连接。 |

除功能表测试外，必须增加“接法测试”：

1. 用 JSON 搭建 PDF 中出现的典型芯片接法。
2. 不新增派生器件，只使用基础门、触发器和 PDF 芯片。
3. 运行仿真，检查输出波形或最终输出。
4. 前端端到端测试中，至少验证这些电路可以被拖拽和连线复现。

必须覆盖的接法测试：

| PDF 接法 | 使用器件 | 验收点 |
| --- | --- | --- |
| `74LS138` 作为数据/时钟分配器 | `74LS138`、输入信号、选择端 | 只有选中通道输出有效。 |
| `74LS148` 扩展为 16-4 编码器 | 两片 `74LS148`、门电路 | 高/低组优先编码和扩展端正确。 |
| `74HC153` 构成 8 选 1 数据选择器 | `74HC153`、门电路 | 8 路选择输出正确。 |
| `7485` 级联成 8 位比较器 | 两片 `7485` | 级联输入输出影响比较结果。 |
| `74283` 级联成 8 位加法器 | 两片 `74283` | 低位进位进入高位。 |
| `74LS194` 构成移位反馈电路 | `74LS194`、门电路 | 左移/右移/反馈接法可原样连接。 |
| `74160` 级联计数 | 两片 `74160` | 同步置数、异步清零和进位输出符合 PDF。 |
| `74161` + `74138` 教学电路 | `74161`、`74138` | 计数状态和译码输出波形正确。 |

## 8. 基本门电路规格与测试

### 8.1 必须实现的门

| 类型 | 名称 | 输入 | 输出 |
| --- | --- | --- | --- |
| `AND` | 与门 | 2 个或更多 | 1 个 |
| `OR` | 或门 | 2 个或更多 | 1 个 |
| `NOT` | 非门 | 1 个 | 1 个 |
| `NAND` | 与非门 | 2 个或更多 | 1 个 |
| `NOR` | 或非门 | 2 个或更多 | 1 个 |
| `XOR` | 异或门 | 2 个或更多 | 1 个 |
| `XNOR` | 同或门 | 2 个或更多 | 1 个 |

### 8.2 门电路测试

必须编写：

1. 每个 2 输入门的完整真值表测试。
2. 多输入 AND/OR/NAND/NOR 测试。
3. `X` 输入传播测试。
4. `Z` 输入读取为不确定的测试。
5. 延迟事件测试：输入在 `t=1` 改变，输出应在 `t=1+delay` 改变。

示例断言：

```text
AND(0, 0) = 0
AND(0, 1) = 0
AND(1, 0) = 0
AND(1, 1) = 1
AND(X, 0) = 0
AND(X, 1) = X
```

## 9. 触发器和锁存器规格与测试

### 9.1 必须实现的触发器

| 类型 | 名称 | 关键输入 | 输出 |
| --- | --- | --- | --- |
| `RS_LATCH_NAND` | 与非门型基本 RS 触发器 | `S_N`、`R_N` | `Q`、`QN` |
| `RS_LATCH_NOR` | 或非门型基本 RS 触发器 | `S`、`R` | `Q`、`QN` |
| `GATED_RS_LATCH` | 门控 RS 锁存器 | `S`、`R`、`EN` | `Q`、`QN` |
| `D_LATCH` | 门控 D 锁存器 | `D`、`EN` | `Q`、`QN` |
| `SYNC_RS_FF` | 同步 RS 触发器 | `S`、`R`、`CP` | `Q`、`QN` |
| `SYNC_D_FF` | 同步 D 触发器 | `D`、`CP` | `Q`、`QN` |
| `SYNC_JK_FF` | 同步 JK 触发器 | `J`、`K`、`CP` | `Q`、`QN` |
| `SYNC_T_FF` | 同步 T 触发器 | `T`、`CP` | `Q`、`QN` |
| `MASTER_SLAVE_RS_FF` | 主从 RS 触发器 | `S`、`R`、`CP` | `Q`、`QN` |
| `MASTER_SLAVE_D_FF` | 主从 D 触发器 | `D`、`CP` | `Q`、`QN` |
| `MASTER_SLAVE_JK_FF` | 主从 JK 触发器 | `J`、`K`、`CP` | `Q`、`QN` |
| `EDGE_D_FF` | 边沿 D 触发器 | `D`、`CP` | `Q`、`QN` |
| `EDGE_JK_FF` | 边沿 JK 触发器 | `J`、`K`、`CP` | `Q`、`QN` |
| `BLOCKING_JK_FF` | 维持-阻塞型 JK 触发器 | `J`、`K`、`CP` | `Q`、`QN` |

### 9.2 触发器通用规则

1. 所有触发器支持初始状态 `initial_q`。
2. 若提供异步 `SET/PRESET` 和 `CLR/RESET`，异步控制优先于时钟。
3. 边沿触发器必须支持 `rising` 和 `falling` 参数。
4. 非法输入产生 `X`，并生成告警。
5. `QN` 始终为 `Q` 的反相；若 `Q=X`，则 `QN=X`。

### 9.3 触发器测试

必须编写：

1. RS 锁存器置位、复位、保持、非法状态测试。
2. D 锁存器透明窗口测试：`EN=1` 时 `Q` 跟随 `D`，`EN=0` 时保持。
3. D 边沿触发器测试：只有指定边沿更新。
4. JK 触发器四种输入测试：保持、复位、置位、翻转。
5. T 触发器保持和翻转测试。
6. 异步清零/置位优先级测试。
7. 初始状态测试。
8. 波形测试：时钟、输入、输出变化点符合预期。

### 10.3 编码器芯片测试

`74LS148`：

1. 使能关闭时输出为非激活状态。
2. 单个输入有效时输出对应编码。
3. 多个输入有效时输出最高优先级编码。
4. 扩展输出/有效输出符合元数据定义。
5. 低有效输入输出必须测试。

`74LS147`：

1. 0 到 9 输入分别有效时输出 BCD 编码。
2. 多输入有效时按优先级输出。
3. 无输入有效时输出非激活状态。
4. 低有效输入输出必须测试。

### 10.4 译码器芯片测试

`74139`：

1. 两组 2-4 译码器独立工作。

`74LS138` / `74138`：

3. 输出低有效规则测试。

`74LS42`：

1. BCD `0000` 到 `1001` 分别激活对应十进制输出。
2. 非法 BCD `1010` 到 `1111` 输出为非激活或 `X`，以元数据约定为准。

`7448`：

1. BCD `0` 到 `9` 输出七段码正确。
2. 非法输入按元数据约定处理。

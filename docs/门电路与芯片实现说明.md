# 门电路与芯片实现说明

## 1. 文档范围

本文档只说明当前已实现的门电路与 PDF 芯片部分，包括：

1. 已实现的基础门电路。
2. 已实现的 PDF 芯片。
3. 使用的核心技术。
4. 现有测试代码覆盖范围。
5. Review 中发现的覆盖缺口和风险点。

触发器/锁存器已有实现和测试，但不作为本文档重点展开。

## 3. 使用技术

| 技术 | 用途 |
| --- | --- |
| C++17 | 实现仿真核心、门电路、触发器和芯片逻辑。 |
| CMake + Ninja | 构建 C++ 静态库、测试可执行文件和 Python 绑定。 |
| GoogleTest | C++ 单元测试。 |
| pybind11 | 将 C++ 仿真核心暴露给 Python。 |

| 事件驱动仿真 | 通过 `Simulator`、`EventQueue`、`WaveRecorder` 记录延迟事件和波形变化点。 |

## 4. 已实现的基础门电路

| 类型 | 实现类 | 支持情况 |
| --- | --- | --- |
| `AND` | `AndGate` | 支持 2 输入和多输入。 |
| `OR` | `OrGate` | 支持 2 输入和多输入。 |
| `NOT` | `NotGate` | 支持单输入反相。 |
| `NAND` | `NandGate` | 支持 2 输入和多输入。 |
| `NOR` | `NorGate` | 支持 2 输入和多输入。 |
| `XOR` | `XorGate` | 支持 2 输入和多输入奇偶逻辑。 |
| `XNOR` | `XnorGate` | 支持 2 输入和多输入同或逻辑。 |

门电路通过 `create_gate(type, id, num_inputs)` 工厂创建。

信号规则支持：

- `0`
- `1`
- `X`
- `Z`

其中 `Z` 在普通逻辑运算中按不确定输入处理。

## 7. Review 结论

### 7.1 齐全性

按当前设计文档和 PDF 芯片清单检查，基础门电路和所有 PDF 芯片均已有 C++ 实现、工厂注册和元数据定义。

清单完整：

- 基础门：7/7。
- PDF 芯片：18/18。
- PDF 别名：`74138`、`74151`、`74194`、`74195`、`74LS161` 等已覆盖。

### 7.2 多余性

没有发现额外的独立派生器件，例如“任意进制计数器”“分频器”“序列发生器”等。

需要注意的是，工厂和元数据中有少量兼容别名：

- `74148`
- `74147`
- `7442`

这些不是独立器件实现，但如果前端将 alias 当成独立卡片展示，就会超出“只展示 PDF 中出现型号”的要求。

### 7.3 测试齐全性

现有测试已经覆盖主要功能表，且统一测试脚本当前通过。

但测试还不能算完全齐全，主要缺口是：

1. 缺少 device-library 元数据结构测试。
2. 缺少 PDF 典型接法测试。
3. Python 绑定测试是脚本式 smoke test，不是标准 pytest 测试。
4. 统一测试脚本发现 C++ 测试失败时只打印 `FAILED`，没有立即退出非零状态。
5. 部分芯片只做功能抽样测试，没有做完整功能表或级联接法测试。

## 9. 仍需关注的问题

### 9.1 `7448` 的 `BI/RBO` 只做了输入消隐

当前实现将 `BIRBO` 作为输入消隐使用。若后续教学需要展示多位数码管前导零消隐，`BI/RBO` 作为 ripple blanking output 的行为需要补充。

### 9.2 Python binding 测试不是标准 pytest

`bindings/python/tests/test_python_binding.py` 中多个测试函数需要 `logic_sim` 参数，但没有 pytest fixture。当前 `test-all.sh` 是直接执行脚本的 `main()`，所以能跑；如果用 `pytest bindings/python/tests`，会失败或行为不一致。

建议改成标准 pytest：

```python
import pytest

@pytest.fixture
def logic_sim():
    import logic_sim
    return logic_sim
```
